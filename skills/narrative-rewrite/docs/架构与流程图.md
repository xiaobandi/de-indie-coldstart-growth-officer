# 叙事改写 · 架构与流程图

## 本技能的四层结构

```mermaid
flowchart TB
  U["使用层：出海冷启动获客官 的使用者"]
  T["触发层：叙事改写"]
  X["执行层：5 个步骤"]
  O["产出层：叙事帖"]
  U --> T --> X --> O
```

| 层 | 内容 |
|---|---|
| 使用层 | 冷启动期 3-6 个月的 C 端/PLG 产品独立开发者，尤其中出海方向；员工定位：产品冷启动期的"增长合伙人"：替你想清楚今天在哪个社区、对谁、说什么话 |
| 触发层 | 关键词 / 显式点名「叙事改写」；触发方式：用户提出需求 |
| 执行层 | **接收输入**：确认拿到的是「开发日志」，先做完整性检查。 → **把技术日志改写为用户视角的 build-in-public 故事**：按该定义执行，并把用到的输入项显式写进产出。 → **交叉校验**：把本步结论与上一步结论对一遍，出现矛盾先解决矛盾再往下走。 → **落盘产出**：按「输出契约」四要素定稿，缺数据的写 `<待填>`。 → **回指自检**：逐个数字回指输入来源，回指不上的删掉。 |
| 产出层 | 叙事帖 |
