# 叙事改写 · 用户场景

> 场景来自本技能的注册表数据与归属员工定义卡，不是通用模板。

**服务对象**：冷启动期 3-6 个月的 C 端/PLG 产品独立开发者，尤其中出海方向

**员工定位**：产品冷启动期的"增长合伙人"：替你想清楚今天在哪个社区、对谁、说什么话

**触发时机**：用户提出需求时

## 场景

| # | 谁 | 什么时机 | 说什么 | 拿到什么 | 注意什么 |
|---|---|---|---|---|---|
| 1 | 冷启动期 3-6 个月的 C 端/PLG 产品独立开发者，尤其中出海方向 | 用户提出需求时 | 「用「叙事改写」处理这份材料：<粘贴或指向文件>」 | 叙事帖 | 缺必需输入时会被要求补充，不会硬跑 |
| 2 | 同上 | 材料齐备、要一次走完 | 同上（材料一次性给全） | 完整产出 + 「未决·待填」清单 | 产出里的每个数字都应能回指到输入 |
| 3 | 同上 | 产出要对外 | 同上，但说明用途是对外 | 停在人工确认闸门，给出待确认项 | 本技能不代替人工发布 |

> 场景围绕「把技术日志改写为用户视角的 build-in-public 故事（开发日志 → 叙事帖）」展开；换一批材料时结论会变，但「谁/时机/要什么/拿到什么/注意什么」这条路径不变。
